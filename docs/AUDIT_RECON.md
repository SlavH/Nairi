## 2. Feature surface map

### chat
- Routes: `app/api/chat/**` (~15: conversations, folders, history, search, share, export, upload, templates, colab, compare-models) + `app/api/nairi-chat`, `app/api/nairi/chat`, `app/api/code-agent`; pages `app/chat`, `app/chat/[id]`
- Key files: `app/api/chat/route.ts` (main streaming, backend selection: colab/ollama/opencode + fallback), `components/chat/chat-interface.tsx`, `nairi-chat-view.tsx`, `chat-sidebar.tsx`, `hooks/use-nairi-chat.ts`, `hooks/use-opencode.ts`, `lib/chat/context-manager.ts`, `lib/chat/multimodal.ts`, `lib/colab/*`
- Integrations: OpenCode (wasm/websocket), Colab backend, Ollama, multiple LLM providers, WebContainer
- Tests: `__tests__/unit/lib/opencode-*.test.ts`, `__tests__/api/...` (none for chat routes directly), `e2e/chat-flow.spec.ts`, `e2e/chat.spec.ts`, `__tests__/integration/api/chat.test.ts`
- Risks: multiple chat backends make behavior divergent; `app/api/chat/route.ts` has `shouldRefuse` safety filter; conversation persistence spans many tables

### builder
- Routes: `app/api/builder/**` (generate, projects CRUD, [id], collaborators, fork); page `app/builder`
- Key files: `app/api/builder/generate/route.ts` (~700 lines, site analysis + generation + quality scoring), `lib/builder/json-normalizers.ts`, `lib/builder/generators/code-cleaner.ts`, `components/builder/live-preview.tsx` (Sandpack), `code-editor.tsx`, `file-explorer.tsx`, `export-options.tsx`, `lib/builder/opencode-prompt.ts`
- Integrations: Sandpack/WebContainer, web search (`lib/builder/utils/web-search.ts`), image gen prompts, OpenCode
- Tests: `__tests__/lib/builder/json-normalizers.test.ts`, `code-cleaner.test.ts`, `__tests__/api/builder/projects/route.test.ts`, `e2e/builder.spec.ts`, `__tests__/integration/api/builder.test.ts`
- Risks: very large route file; code cleaning is regex-heavy (fragile); Sandpack preview sanitation critical (XSS)

### marketplace
- Routes: `app/api/marketplace/**` (~15: agents CRUD/install/reviews, products CRUD/purchase, earnings, recommendations, search); pages `app/marketplace/**`
- Key files: `components/marketplace/creator-dashboard.tsx`, `create-agent-form.tsx`, `app/api/marketplace/agents/[agentId]/install/route.ts`, `earnings/route.ts`, `purchase/route.ts`, `lib/marketplace/recommendation.ts`, `lib/features/marketplace/index.ts`
- Integrations: Stripe (webhooks, product_purchases), Supabase (RLS on purchases/subscriptions now hardened), credits
- Tests: `__tests__/integration/api/marketplace.test.ts`, `e2e/marketplace.spec.ts`
- Risks: payment/purchase flows need strict RLS (hardening migration just added); earnings math in `earnings/route.ts` is complex (116 lines of credit computation)

### learn (NairiBook)
- Routes: `app/api/learn/**` (notebooks CRUD + sources + chat + generate, quizzes, ai-mentors, progress, achievements); pages `app/learn/**`
- Key files: `lib/nairibook/*` (23 modules: pipeline, chunking, concepts, graph, srs, exercises, problem, rag, retrieval, embeddings/WebGPU, photo-check, zen, opfs, parsers epub/pdf/text), `lib/learn/{achievements,ai-mentors,progress-tracker,quizzes,url-research}.ts`, `components/learn/*`
- Integrations: transformers.js (WebGPU embeddings), tesseract (photo-check OCR), pdfjs/epub parsers, OFS/IndexedDB, AI mentors (RAG)
- Tests: `__tests__/lib/nairibook/{core,exercises,photo-check,problem,retrieval}.test.ts`, `e2e/learn.spec.ts`
- Risks: client-side heavy (OPFS/IndexedDB/WebGPU) → inconsistent between browsers; SRS + gamification state juggling

## 6. Cross-cutting observations

- Shared `lib/ai/*` used by chat, builder, learn, studio (single source for provider routing, fallback, circuit breaking) — auditing it once covers all areas
- `lib/supabase/*` (server/client/admin) shared everywhere; RLS policy correctness is the single biggest security lever (new hardening migration addresses known vulns)
- `lib/rate-limit*` + `lib/features/*` (per-feature usage gates) span chat/builder/studio/learn
- Duplication: chat backends (colab vs ollama vs opencode vs direct) are inconsistent; `generate-*` routes repeat key-validation + rate-limit boilerplate
- `tasks.json`, `nairi_v34_res/`, `audit_runs/` contain prior manual audit artifacts (useful cross-reference)
- `next-env.d.ts` flips between `.next/types` and `.next/dev/types` depending on build mode (harmless, generated)
